## Why the next run targets Supplements.Kernels.MainTheorems

The root Main.lean imports:

- Statements;
- Supplements.Kernels.MainTheoremsAll.

MainTheoremsAll imports MainTheoremsCritical and CorGKOf; MainTheoremsCritical adds small-class-number modules. Those are not needed to expose the RH/Dirichlet-L-function theorem chain.

The actual theorem wrappers used for the headline conclusions are defined in Supplements.Kernels.MainTheorems:

- allChi;
- rhOfAll;
- critAll;
- claimAll.

The module imports MainConclusion, ClaimStrip, and the gamma-factor/functional-equation bridge. Its dependency closure contains the mathematical theorem chain under audit. Building this module directly avoids making the first verification attempt depend on the additional small-class-number imports pulled in by MainTheoremsAll.

The targeted axiom script now imports Statements and Supplements.Kernels.MainTheorems, then prints dependencies for:

- allChi, rhOfAll, critAll, claimAll;
- UpperTheory.FinalTheorems.everyCharacter_of_row;
- UpperTheory.FinalTheorems.everyCharacter;
- UpperTheory.FinalTheorems.riemannHypothesis;
- Formalism.VW.rh_of_every;
- Formalism.VW.critLine.

The workflow also caches upstream .lake/build and Mathlib build artifacts to make retries incremental where the Actions cache is available.
